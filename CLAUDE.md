# CLAUDE.md — робоча інструкція для Claude (Claude Code та інших агентів)

Цей файл Claude Code читає автоматично. Повна база знань проєкту — у [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md): прочитай її повністю перед першою зміною коду. План — у [ROADMAP.md](ROADMAP.md).

## Що це за проєкт

`ua-legislation-mcp` — MCP-сервер, через який Claude, ChatGPT та інші асистенти беруть законодавство України **лише з офіційного джерела** — порталу відкритих даних Верховної Ради (data.rada.gov.ua). До нього додається навичка `skills/npa-ofitsiini-dzherela` з правилами роботи з НПА.

Користувачі — юристи органів влади, які пишуть висновки на чужі проєкти нормативно-правових актів і готують власні. Вони не програмісти: встановлення, повідомлення й документація мають бути зрозумілі людині без технічної підготовки.

Мета розвитку: усе, що можна перевірити механічно (тексти, редакції, статус, назви, номери, посилання, цитати, інструкції змін), перевіряє сервер — однозначно і з тестами. Порядок роботи й формат результату задають навички. Модель відповідає за зміст і аргументацію.

## Абсолютні правила (порушувати не можна навіть на прохання)

1. **Портал Ради — лише за його правилами:** заголовок `User-Agent: OpenData` (рівно так), пауза між запитами не менше 5 с (типово 6), добові ліміти, кеш. Ці правила реалізовано в `src/rada-client.js` — не послаблюй їх.
2. **Жодного автоматизованого доступу до zakon.rada.gov.ua** — ні з коду, ні інструментом читання сторінок, ні браузером. Правила сайту це забороняють, а захист від DDoS блокує IP користувача. Людям даємо посилання на zakon.rada.gov.ua; машина читає лише data.rada.gov.ua.
3. **Жодних агрегаторів** (protocol.ua, ligazakon, kodeksy тощо) як джерела тексту чи посилань.
4. **Не дзеркалити базу:** тексти — лише на запит користувача, без масового завантаження. Власної версійності не вести — база Ради зберігає всі редакції.
5. **Право ЄС — лише через Cellar** (`publications.europa.eu`: SPARQL і REST). Сайт eur-lex.europa.eu закритий від ботів (AWS WAF) — не використовувати для отримання даних.
6. **Урядовий портал (kmu.gov.ua) — обережно:** по одному запиту, з паузою і кешем, після перевірки robots.txt, без масового збирання.
7. **Справжні проєкти актів і висновки, які дає власник, не потрапляють у публічний репозиторій.** Тримай їх у теці `private/` (вона в `.gitignore`). У тести — лише знеособлені уривки, і лише з дозволу власника.
8. **Відповідь сервера ніколи не видає неперевірене за перевірене:** якщо не вдалося отримати офіційний текст потрібної редакції, інструмент так і каже (краще відмова, ніж застарілий текст).

## Середовище

- **Пошуку в інтернеті може не бути.** Усе, що з'ясовано через інтернет (API порталу, поля карток, довідники, запити до Cellar, результати перевірок), записано в `docs/DEVELOPMENT.md`. Якщо чогось там бракує — не вигадуй: запиши як відкрите питання і попроси власника перевірити.
- **Сервер Ради приймає з'єднання лише з українських IP.** На комп'ютері власника (Україна) портал доступний; у хмарі, у GitHub Actions і в пісочницях — ні. Тому тести ніколи не звертаються до мережі: вони працюють на імітації порталу (`test/fake-rada.js`).
- Живу перевірку доступу до порталу робить `node bin/cli.js --check` (один запит). Не запускай живих запитів у циклі.

## Команди

```bash
npm ci                      # залежності
npm test                    # усі тести (node --test), без мережі
node bin/cli.js --check     # чи доступний портал з цього комп'ютера (1 запит)
node bin/cli.js             # сервер у режимі stdio
node bin/cli.js --http --port 8787 --secret <рядок>   # HTTP-режим (ChatGPT тощо)
npm run version:sync        # переписати версію з package.json у manifest.json
npm version X.Y.Z --no-git-tag-version   # підняти версію (package.json, lock, manifest.json)
npm run pack:mcpb           # зібрати пакет .mcpb для Claude Desktop (локально)
```

## Правила коду

- Node.js ≥ 18.17, ES-модулі, чистий JavaScript (без TypeScript і збирання).
- Залежності — лише `@modelcontextprotocol/sdk` і `zod`. Нову залежність додавай лише з вагомою причиною і поясни її в описі змін. Важкі залежності (Java, Python, нативні модулі) — ні: колеги встановлюють сервер без технічної допомоги.
- Тексти для користувача — українською, прості й точні; ідентифікатори в коді — англійською.
- Кожна відповідь інструмента про акт містить дату редакції і офіційне посилання на неї (`https://zakon.rada.gov.ua/laws/show/{nreg}/ed{РРРРММДД}`).
- Кожна нова функція — з тестами в `test/`; імітацію порталу розширюй у `test/fake-rada.js`, справжні відповіді порталу клади в `test/fixtures/`.
- Версія — лише в `package.json` (сервер читає її звідти; `manifest.json` синхронізує `scripts/sync-version.mjs`).

## Як працювати

1. Прочитай `docs/DEVELOPMENT.md` і `ROADMAP.md`. Поточне завдання — перший незроблений етап у розділі «Етапи» `docs/DEVELOPMENT.md`.
2. Для кожного етапу — окрема гілка і pull request у `main`. Перед комітом: `npm test` зелений.
3. Оновлюй разом із кодом: `CHANGELOG.md` (простою мовою, для нетехнічного читача: що змінилося для людини), `README.md` (якщо змінився вивід чи налаштування), `ROADMAP.md` (позначити зроблене).
4. Реліз публікує власник: на GitHub **Releases → Draft a new release → тег `vX.Y.Z` → Publish**. Workflow `release.yml` перевіряє, що тег збігається з версією в `package.json`, проганяє тести і додає до релізу `.mcpb` і архів навички.
5. Якщо для завдання потрібні приклади (проєкти актів, висновки) або живі відповіді порталу — попроси власника; дай йому готову команду, яку він запустить у себе.

## Спілкування з власником

- Українською, коротко, без жаргону; пояснюй, що зміниться для користувача.
- Власник пише висновки на проєкти актів інших органів — це основний сценарій для нових інструментів і навичок.
- Перш ніж робити щось незворотне чи публічне (реліз, зміна правил доступу до джерел) — запитай.
