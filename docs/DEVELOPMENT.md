# База знань для розробки

Документ для агента (Claude, Claude Code) або людини, які продовжують розробку **без доступу до пошуку в інтернеті**. Тут зібрано все, що з'ясовано раніше: як влаштовано код, як працюють джерела, що перевірено на живих даних, які рішення ухвалено і чому, а також детальні специфікації наступних етапів.

Позначки достовірності:
- **перевірено** — підтверджено живим запитом або кодом, що працює;
- **з джерела** — взято з документації чи сторінки джерела, живим запитом не перевірялося;
- **припущення** — висновок, який треба підтвердити, перш ніж на нього спиратися.

## 1. Стан проєкту

Версія **0.1.3** (опублікована з `main` після 28.11.2026; v0.1.1 і v0.1.2 уже є в Releases).

**Інструменти MCP** (`src/server.js`):

| Інструмент | Що робить |
|---|---|
| `search_acts` | пошук актів за назвою, номером, датою прийняття чи роком у локальному переліку документів (`doc.txt`) |
| `get_act_card` | картка акта: статус, вид, видавник, реквізити, назва англійською, законопроєкт, офіційне опублікування, поточна і майбутні редакції (з умовою набрання чинності), історія редакцій |
| `get_act_text` | текст у поточній або будь-якій редакції: стаття (`article`), пошук фрагмента (`find`), зміст (`outline`), посторінково (`offset`); над текстом — заголовок із попередженнями про майбутні редакції й архівну копію |
| `check_act_editions` | для переліку актів із датами редакцій, на які спирається документ: чи змінилося щось після цих дат (завжди свіжа картка) |
| `list_recent_updates` | стрічка нещодавно оновлених документів (`r.tsv`) |
| `service_status` | запити й обсяг за добу, кеш, стан індексу |
| `search`, `fetch` | сумісні інструменти для ChatGPT (типово лише в HTTP-режимі; `RADA_COMPAT_TOOLS`) |

**Навичка:** `skills/npa-ofitsiini-dzherela/SKILL.md` — офіційні джерела, коди nreg, канали доступу, перевірка актуальності, реєстр джерел у кінці кожного документа, повторна перевірка, цитування. До кожного релізу додається архівом `npa-ofitsiini-dzherela.zip`.

**Встановлення:** пакет `.mcpb` для Claude Desktop (з релізу); `npx -y github:Rmonakov/ua-legislation-mcp` для інших клієнтів; HTTP-режим із секретним шляхом для ChatGPT (через тунель). Покрокова інструкція для Windows — `docs/windows.md`.

**CI:** `.github/workflows/test.yml` — тести на Linux/Windows/macOS і кількох версіях Node; `release.yml` — на подію `release: published` перевіряє тег проти `package.json`, проганяє тести, збирає `.mcpb` (`npx -y @anthropic-ai/mcpb pack`) і архів навички, додає їх до релізу.

## 2. Архітектура коду

| Файл | Відповідальність |
|---|---|
| `bin/cli.js` | точка входу: stdio (типово), `--http` (Streamable HTTP без стану, `--port`, `--host`, `--secret`), `--check`, `--version` |
| `src/config.js` | конфігурація зі змінних середовища (`RADA_*`), тека кешу, `VERSION` з `package.json`; `clean()` відкидає незаповнені шаблони `${user_config.x}` від Claude Desktop |
| `src/http.js` | `httpGet` на вбудованих модулях Node (gzip/deflate/br, ліміт розміру, тайм-аут) |
| `src/rada-client.js` | `RadaClient`: черга запитів із паузою, добові ліміти (кількість і МБ), кеш на диску, умовні запити (ETag / Last-Modified, 304), картки, тексти, довідники, стрічка оновлень, дамп `doc.txt` |
| `src/index-store.js` | `IndexStore`: локальний індекс назв усіх документів з `doc.txt` (у пам'яті), пошук, фонове оновлення раз на тиждень, відкат 30 хв після невдачі |
| `src/text.js` | робота з текстом акта: класифікація рядків (стаття / розділ / примітка `{…}`), зміст, витяг статті, пошук фрагмента, посторінковий вивід |
| `src/format.js` | розбір картки (`summarizeCard`), текст картки (`cardToText`), дати, статуси, підстави (`4196-20` → «№ 4196-IX»), опублікування (`publics`), майбутні редакції, посилання |
| `src/cp1251.js` | декодування Windows-1251; `charsetOf` / `decodeText` — кодування за Content-Type з урахуванням опечатки порталу |
| `src/server.js` | реєстрація інструментів MCP (zod-схеми), тексти відповідей, `structuredContent`, метадані для `fetch` |
| `scripts/sync-version.mjs` | версія з `package.json` → `manifest.json`; `--check`, `--expect X.Y.Z` (для релізу) |
| `manifest.json` | маніфест пакета MCPB (manifest_version 0.3) з `user_config` (тека кешу, пауза, ліміти) |
| `test/` | `unit.test.js`, `client.test.js`, `mcp.test.js`; `fake-rada.js` — імітація порталу; `fixtures/1315-18.card.json` — справжня картка |

**Кеш** (тека з `RADA_CACHE_DIR` або системна тека кешу; якщо не можна писати — тимчасова):
- `cards/` — картки, свіжі `RADA_CARD_TTL_MINUTES` (типово 6 год);
- `texts/` — тексти конкретних редакцій (незмінні, зберігаються назавжди);
- `dicts/{typ,organs,pubs,stan}.txt` + `*.meta.json` — довідники, 30 днів, далі умовний запит;
- `updates.tsv` + `.meta.json` — стрічка оновлень, 30 хв, далі умовний запит;
- `index/doc.txt` + `.meta.json` — перелік документів, 7 днів, далі умовний запит;
- лічильник використання за добу.

**Умовні запити:** `_getConditional(path, file, ttlMs)` зберігає поруч `*.meta.json` (`etag`, `lastModified`, `contentType`, `savedAt`); коли строк минув — надсилає `If-None-Match` / `If-Modified-Since`; на 304 бере кеш і подовжує строк (оновлює mtime). `ttlMs <= 0` — завжди перевіряти.

## 3. Портал відкритих даних Ради — довідник

### 3.1. Правила доступу (перевірено / з джерела)

- Базова адреса: `https://data.rada.gov.ua`.
- Заголовок `User-Agent: OpenData` — без нього анонімний доступ до TXT/JSON не працює (**перевірено**).
- Ліміти порталу: до 60 запитів на хвилину, 100 000 на добу, 200 МБ на добу (**з джерела**). Наші типові налаштування суворіші: пауза 6 с, 2000 запитів і 150 МБ на добу.
- **Сервер приймає з'єднання лише з українських IP** — закордонні й хмарні адреси відхиляються (**перевірено**). Тому розробка з живими даними можлива лише на комп'ютері в Україні.
- Портал надсилає `ETag` і `Last-Modified` для файлів відкритих даних і відповідає 304 на умовний запит (**перевірено** на `pubs.txt`: `ETag: "e6a-657931349c4d1"`, `Last-Modified: Mon, 27 Jul 2026 07:57:35 GMT`).
- **Опечатка порталу:** `Content-Type: text/plain; charset=widows-1251` (саме «widows»). Кодування визначаємо за «1251» (**перевірено**).
- Сторінки каталогу `https://data.rada.gov.ua/open/data/...` закриті для роботів (robots.txt); машинні файли лежать у `/ogd/...` і `/laws/...`.
- zakon.rada.gov.ua — **не чіпати автоматично** (див. CLAUDE.md).

### 3.2. Точки доступу

| Що | Адреса | Формат |
|---|---|---|
| Картка документа | `/laws/card/{nreg}.json` (те саме дає `/laws/show/{nreg}.json`) | JSON, UTF-8 |
| Текст поточної редакції | `/laws/show/{nreg}.txt` | текст (декодування за Content-Type) |
| Текст редакції на дату | `/laws/show/{nreg}/ed{РРРРММДД}.txt` | текст |
| Стрічка оновлень | `/laws/main/r.tsv` | TSV |
| Перелік усіх документів | `/ogd/zak/laws/data/csv/doc.txt` (~52 МБ) | TSV, Windows-1251 |
| Довідники | `/ogd/zak/laws/data/csv/{name}.txt` | TSV `код⇥назва`, Windows-1251 |
| Пошук | `/laws/find/a?text=...` | (використовується обмежено; основний пошук — локальний індекс) |

У `nreg` кирилицю кодуємо (%-кодування UTF-8), скісну риску (`254к/96-вр`) лишаємо як є (`encodeNregPath` у `format.js`).

### 3.3. Коди документів (nreg)

- закон: номер + скликання, де скликання = римське скликання + 11: № 1315-VII → `1315-18`, № 2939-VI → `2939-17`, IX скликання → `-20`;
- постанова КМУ: `1337-2003-п`; розпорядження КМУ: `1163-2014-р`;
- наказ, зареєстрований у Мін'юсті: `z0186-15`;
- Конституція: `254к/96-вр`.

Завжди звіряй за карткою: шаблони мають винятки.

### 3.4. Картка: поля (перевірено на справжній картці 1315-18, `test/fixtures/1315-18.card.json`)

| Поле | Зміст |
|---|---|
| `dokid` | внутрішній номер документа |
| `nreg` | код документа |
| `nazva` | назва |
| `status` | стан (довідник `stan`, див. нижче) |
| `typ`, `types` | вид документа (довідник `typ`); `types` — число або рядок `a\|b` |
| `org`, `organs` | видавник (довідник `organs`); `organs` — `код:РРРРММДД:номер`, через `\|` |
| `orgdat`, `orgnum`, `n_vlas` | дата прийняття, номер (`1315-VII`) |
| `pridat` | **дата прийняття** (не дата набрання чинності редакцією — раніше тут була помилка) |
| `poddat`, `pidstava` | дата і підстава поточної редакції |
| `eds[]` | редакції: `{podid, datred, pidstava, comment?, size}`; `datred` — РРРРММДД; `30000101` — дата не визначена |
| `eds[].comment` | умова для майбутньої редакції, напр. «з дня припинення чи скасування воєнного стану» |
| `eds_dates` | дати редакцій |
| `hist[]` | події історії: `{podid, poddat, pidstava, comments?}`; `comments` — `{nreg_підстави: "! текст"}` |
| `history` | історія рядком |
| `is_archive` | `0` / `1` — архівна копія (портал віддає саме `is_archive`, не `isArchive`) |
| `links` | лише лічильники зв'язків за видами (напр. `510864#1:6\|2:8\|...#`) — повні переліки в `links.csv` |
| `anots[]` | `{ann_nam, ann_dat, ...}` — `ann_nam` — назва англійською |
| `projs[]` | законопроєкт: `{proj_num, proj_dat (ДД.ММ.РРРР), proj_nam}` |
| `publics` | опублікування: `дата:код_видання:реквізити`, через `\|` |
| `minjust` | реєстрація в Мін'юсті |
| `terms`, `termcnt` | терміни (визначення) — **припущення**: не досліджено |

Коди подій `hist[].podid` (**припущення** за справжніми картками; підтвердити довідником `podia`): 4 — прийняття, 30 — ймовірно опублікування, 1 — набрання чинності, 0 — редакція, 3 — втрата чинності.

Стани (`stan`, реалізовано в `format.js`): 0 — не визначено; 1 — втратив чинність; 2 — набирає чинності; 3 — дію зупинено; 4 — дію відновлено; 5 — чинний; 6 — не набрав чинності; 7 — не застосовується на території України; 8 — частково набрав чинності; 9 — втратив чинність, крім окремих положень.

### 3.6. Перелік документів `doc.txt`

TSV у Windows-1251, колонки: `dokid, nreg, nazva (може містити табуляції), status, types, organs, minjust, npix, poddat`. Розбір — `parseDocLine` в `index-store.js`: назва — усе між другою колонкою і останніми шістьма. `organs` — `код:дата:номер` через `|`.

### 3.7. Стрічка оновлень `r.tsv`

Колонки: `num, card, nazva, status, publics, link, size, file`. `nreg` береться з колонки `link` (`nregFromLink`), а не з `num`.

### 3.8. Текст акта

Один логічний абзац на рядок. Примітки про зміни — у фігурних дужках `{…}` (можуть займати кілька рядків). Заголовки: «Стаття N. Назва», «Розділ …», «Глава …». Номери статей з надрядковими цифрами (`23¹`) нормалізуються до `23-1` (`normalizeArticleId`).

## 4. Право ЄС: Cellar — довідник

Cellar — сховище Бюро публікацій ЄС, на якому працює EUR-Lex. Повторне використання даних EUR-Lex безкоштовне (з дотриманням умов авторського права); громадяни й компанії можуть автоматизовано звертатися до публічної SPARQL-точки (**з джерела**). Чітких лімітів не знайдено — працюємо так само ввічливо, як із порталом Ради: черга, пауза, кеш.

### 4.1. Точки доступу (перевірено 28.11.2026)

- **SPARQL:** `https://publications.europa.eu/webapi/rdf/sparql`, `GET ?query=...`, `Accept: application/sparql-results+json`. Відповідь за 0,1–1 с на точкових запитах.
- **Текст акта (REST):** `GET https://publications.europa.eu/resource/celex/{CELEX}` із заголовками `Accept: application/xhtml+xml` і `Accept-Language: eng` → після переадресацій XHTML (UTF-8). Для консолідованої версії eIDAS `02014R0910-20241018` — 454 927 байтів. `Accept: text/html` для актів повертає 404 (HTML є лише для рішень суду). `Accept-Language` — тризначний код ISO 639-2/T (`eng`, `deu`, `fra`, `pol`), не `ger`/`fre`.
- Formex XML: `Accept: application/xml;type=fmx4` (для багаточастинних актів — 300 Multiple Choices з переліком частин) — **з джерела**, не перевірено.
- **eur-lex.europa.eu не використовувати:** перед ним AWS WAF, що віддає роботам JavaScript-заглушку замість тексту.

### 4.2. CELEX

`{сектор}{рік}{тип}{номер з нулями до 4 цифр}`:
- сектор 3 — законодавство (`32016R0679` — GDPR; `R` регламент, `L` директива, `D` рішення);
- сектор 0 — консолідовані тексти: `0{рік}{тип}{номер}-{РРРРММДД}` (`02014R0910-20241018`);
- сектор 1 — договори, 6 — судова практика, 7 — національні заходи транспозиції: `7{CELEX директиви}{ISO3}_{id}` (`72022L2555POL_202601954`).

### 4.3. Властивості CDM (перевірено на `32014R0910`)

Префікс `cdm: <http://publications.europa.eu/ontology/cdm#>`:
- `resource_legal_id_celex` — CELEX (літерал `xsd:string`);
- `work_date_document` — дата акта;
- `resource_legal_in-force` — `1` чинний / `0` ні;
- `resource_legal_date_entry-into-force` — дата(и) набрання чинності (може бути кілька: у eIDAS 2014-09-17 і 2016-07-01);
- `resource_legal_date_end-of-validity` — кінець дії; `9999-12-31` — безстроково;
- `resource_legal_eli` — ELI (`http://data.europa.eu/eli/reg/2014/910/oj`);
- `resource_legal_type` (`R`), `resource_legal_year`, `resource_legal_number_natural`;
- `work_has_resource-type` — вид (`.../resource-type/REG`);
- `resource_legal_amends_resource_legal`, `resource_legal_repeals_resource_legal`, `resource_legal_implicitly_repeals_resource_legal`, `resource_legal_based_on_resource_legal` (правова основа), `resource_legal_adopts_resource_legal`, `work_cites_work`;
- `act_consolidated_based_on_resource_legal` — консолідована версія → базовий акт; `act_consolidated_date` — дата консолідації;
- `measure_national_implementing_implements_resource_legal` — національний захід → директива;
- `directive_date_transposition` — строк транспозиції;
- назва: вираз (`expression`) мовою: `?e cdm:expression_belongs_to_work ?w ; cdm:expression_uses_language <http://publications.europa.eu/resource/authority/language/ENG> ; cdm:expression_title ?t`.

Дати дії за типами (набрання чинності, застосування, часткове застосування) зберігаються як анотації (`annotation:type_of_date`) — див. реалізацію `act-citation.ts` у cyanheads/eur-lex-mcp-server, якщо знадобиться.

### 4.4. Перевірені запити

Картка акта:
```sparql
PREFIX cdm: <http://publications.europa.eu/ontology/cdm#>
PREFIX xsd: <http://www.w3.org/2001/XMLSchema#>
SELECT ?work ?date ?inForce ?eif ?eov ?eli ?title WHERE {
  ?work cdm:resource_legal_id_celex "32014R0910"^^xsd:string .
  OPTIONAL { ?work cdm:work_date_document ?date }
  OPTIONAL { ?work cdm:resource_legal_in-force ?inForce }
  OPTIONAL { ?work cdm:resource_legal_date_entry-into-force ?eif }
  OPTIONAL { ?work cdm:resource_legal_date_end-of-validity ?eov }
  OPTIONAL { ?work cdm:resource_legal_eli ?eli }
  OPTIONAL { ?expr cdm:expression_belongs_to_work ?work ;
                   cdm:expression_uses_language <http://publications.europa.eu/resource/authority/language/ENG> ;
                   cdm:expression_title ?title }
} LIMIT 5
```
Результат: `inForce=1`, `eif=2014-09-17` і `2016-07-01`, `eov=9999-12-31`, ELI, назва.

Чим змінено або скасовано:
```sparql
PREFIX cdm: <http://publications.europa.eu/ontology/cdm#>
PREFIX xsd: <http://www.w3.org/2001/XMLSchema#>
SELECT ?rel ?celex ?date WHERE {
  ?target cdm:resource_legal_id_celex "32014R0910"^^xsd:string .
  { ?other cdm:resource_legal_amends_resource_legal ?target . BIND("amended_by" AS ?rel) }
  UNION { ?other cdm:resource_legal_repeals_resource_legal ?target . BIND("repealed_by" AS ?rel) }
  ?other cdm:resource_legal_id_celex ?celex .
  OPTIONAL { ?other cdm:work_date_document ?date }
} ORDER BY ?date
```
Результат: `amended_by 32022L2555 (2022-12-14)`, `amended_by 32024R1183 (2024-04-11)`.

Консолідовані версії (найновіша перша):
```sparql
PREFIX cdm: <http://publications.europa.eu/ontology/cdm#>
PREFIX xsd: <http://www.w3.org/2001/XMLSchema#>
SELECT ?celex ?cdate WHERE {
  ?base cdm:resource_legal_id_celex "32014R0910"^^xsd:string .
  ?c cdm:act_consolidated_based_on_resource_legal ?base ;
     cdm:resource_legal_id_celex ?celex .
  OPTIONAL { ?c cdm:act_consolidated_date ?cdate }
} ORDER BY DESC(?cdate) LIMIT 5
```
Результат: `02014R0910-20241018`, `02014R0910-20240520`, `02014R0910-20140917`.

SELECT ?celex ?date WHERE {
  ?dir cdm:resource_legal_id_celex "32022L2555"^^xsd:string .

Результат: `inForce=0`, `eov=2018-05-24`, `by=32016R0679`.

### 4.5. Консолідований текст (XHTML)

- Починається із застереження: «This text is meant purely as a documentation tool and has no legal effect… The authentic versions of the relevant acts… are those published in the Official Journal…» — сервер має повідомляти, що консолідований текст довідковий, а автентичний — в Official Journal.
- Позначки змін: `►B` (базовий акт), `►M1`, `►M2` (зміни за переліком «Amended by»), `▼…` — їх прибирати з цитати.
- Ідентифікатори елементів: `id="art_5a"`, `id="art_5a.tit_1"`, `id="cpt_I"` — збігаються зі схемою Akoma Ntoso, яку ми беремо для українських текстів.
- Класи: `eli-subdivision`, `title-article-norm`, `stitle-article-norm`, `norm`, `disclaimer`, `modref`.

## 5. Український контекст для перевірок

Нижче — типові формулювання в українських НПА і проєктах. Це **робоча гіпотеза для розбору**: уточнюй на справжніх прикладах власника, перш ніж закріплювати в коді.

### 5.1. Посилання на акти

- «Закон України від 05.06.2014 № 1315-VII «Про стандартизацію»», «Закону України «Про стандартизацію»» (назва в лапках не відмінюється, відмінюється вид акта), «Кодекс адміністративного судочинства України», «Конституція України».
- «постанова Кабінету Міністрів України від 01.04.2026 № 438 «Про …»», «розпорядження Кабінету Міністрів України від … № …-р».
- «наказ Міністерства … від … № …, зареєстрований у Міністерстві юстиції України … за № …/…».
- Указ Президента: «Указ Президента України від … № …/РРРР».
- Акти ЄС українською: «Регламент (ЄС) 2016/679 Європейського Парламенту та Ради від 27 квітня 2016 року …», «Директива 2002/58/ЄС», «Директива (ЄС) 2022/2555», «Директива Ради 93/13/ЄЕС», «Рішення …», «Імплементаційний регламент Комісії (ЄС) 2021/1165».

Перетворення на CELEX: до 2015 р. регламенти — «№ номер/рік» (`№ 910/2014` → `32014R0910`), директиви — «рік/номер» (`2002/58/ЄС` → `32002L0058`, `95/46/ЄС` → `31995L0046`); з 2015 р. для всіх видів — «рік/номер» (`(ЄС) 2016/679` → `32016R0679`). «ЄС» в українських текстах означає і EU, і EC (Європейське співтовариство); «ЄЕС» — EEC; на CELEX це не впливає.

### 5.2. Структурні елементи

Розділ → глава → (параграф) → стаття → частина → пункт → підпункт → абзац. У законах частини статті зазвичай нумеровані «1.», «2.»; пункти — «1)», «2)»; підпункти — «а)», «б)». У постановах КМУ пункти — «1.», підпункти — «1)». У посиланнях частини називають порядковими словами: «частина перша статті 23», «пункт 3 частини другої», «абзац другий пункту 5». Нумерація залежить від виду акта — перевіряй на справжніх текстах.

Ідентифікатори елементів (Akoma Ntoso): `sec_II` (розділ), `chp_3` (глава), `art_23`, `art_23__para_1` (частина), `art_23__para_1__point_3` (пункт), `…__point_3__subpoint_a` (підпункт), `…__subpara_2` (абзац). Наприклад, «пункт 3 частини першої статті 23» → `art_23__para_1__point_3`.

### 5.3. Інструкції змін (для `check_amendments`)

Типові формулювання: «у частині першій статті 23 слова «…» замінити словами «…»»; «… доповнити словами «…»»; «… після слів «…» доповнити словами «…»»; «слова «…» виключити»; «статтю 5 викласти в такій редакції: …»; «доповнити статтею 5-1 такого змісту: …»; «пункт 3 виключити. У зв'язку з цим пункти 4–7 вважати відповідно пунктами 3–6»; «у тексті Закону слова «…» в усіх відмінках замінити словами «…» у відповідному відмінку».

Що перевіряти механічно: існує згаданий елемент у чинній (або майбутній) редакції; слова, які пропонують замінити чи виключити, справді є в цьому елементі; після слів «…» — ці слова є; нумерація після виключень узгоджена; колонка «Чинна редакція» порівняльної таблиці дослівно збігається з офіційним текстом.

### 5.4. Ідентифікатори актів (ELI-подібна схема, чернетка)

- акт у редакції: `eli/ua/zakon/2014/06/05/1315-VII/2025-08-28`;
- елемент: `…/2025-08-28#art_23__para_1`;
- для людей основне посилання — `https://zakon.rada.gov.ua/laws/show/1315-18/ed20250828`.

Україна не публікує законодавство за ELI — схема неофіційна, але за правилами ELI.

## 6. Етапи і завдання

Порядок обов'язковий: наступний етап — після того, як попередній злитий і власник погодив. Кожен етап — гілка, PR, зелені тести, оновлені CHANGELOG/README/ROADMAP.

### Етап 0.2а. Структура тексту за Akoma Ntoso

**Мета:** сервер розуміє текст до рівня «пункт 3 частини першої статті 23».

- Новий модуль `src/structure.js`: `parseStructure(text)` → дерево `{type, num, eId, heading?, lineStart, lineEnd, children}` для розділів, глав, статей, частин, пунктів, підпунктів, абзаців; примітки `{…}` — окремо, не частина норми.
- `locate(tree, ref)`: розбір посилання українською («пункт 3 частини першої статті 23», «абзац другий пункту 5», «підпункт «а» пункту 2») → `eId` → текст елемента; порядкові слова «перша…двадцята», «другий…» у відмінках.
- `get_act_text` отримує параметр `element` (українське посилання або `eId`).
- **Готово, коли:** тести на 3+ справжніх текстах різних видів (закон, кодекс, постанова КМУ) — тексти дає власник (див. розділ 7); посилання «частина N статті M» знаходяться в усіх них; невідомий елемент → чітка відмова з переліком наявних.

### Етап 0.2б. `check_references`

**Вхід:** текст (проєкт акта або висновку), до ~200 000 символів; опційно дата, на яку перевіряти.

**Що робить:** знаходить згадки актів (розділ 5.1) → визначає вид, дату, номер, назву в лапках → шукає в локальному індексі (`IndexStore`; `organs` містить `код:дата:номер`) → для кожного: `nreg`, статус, чинна назва (і чи збігається з написаною), чи існують згадані структурні елементи (через 0.2а; текст береться через `RadaClient`, з дотриманням пауз — тож для великої кількості актів інструмент працює повільно і має показувати прогрес або обмежувати кількість).

**Вихід:** таблиця `згадка у тексті → nreg → статус → назва (збігається / інша: «…») → елемент (є / немає) → посилання на редакцію`; окремо — нерозпізнані згадки.

**Готово, коли:** на знеособлених прикладах власника інструмент знаходить усі згадки, які знайшла людина, і не дає хибних «не знайдено» для правильних посилань.

### Етап 0.2в. `check_amendments`

**Вхід:** текст проєкту змін (і, за бажання, порівняльна таблиця).

**Що робить:** розбирає інструкції змін (розділ 5.3), знаходить змінюваний акт і елемент, перевіряє слова й нумерацію в чинній редакції (або в майбутній, якщо проєкт набирає чинності після неї); звіряє колонку «Чинна редакція» з офіційним текстом.

**Вихід:** перелік інструкцій із позначками «можна застосувати» / «немає такого елемента» / «немає таких слів» / «текст колонки не збігається» (з різницею).

## 8. Уроки й підводні камені

- `.mcpbignore`: шаблон `dist/` без `/` виключав `node_modules/@modelcontextprotocol/sdk/dist` і ламав пакет — використовуй закорені шаблони (`/dist/`, `/test/`).
- Claude Desktop передає незаповнені поля `user_config` як буквальний `${user_config.x}` — `clean()` у `config.js`; шлях до кешу має бути абсолютним і доступним для запису, інакше — запасна тека.
- Індекс `doc.txt` (~52 МБ) колись завантажувався при кожному пошуку — тепер у пам'яті, відкат 30 хв, умовні запити.
- `nreg` у `r.tsv` — з колонки посилання, не з `num`.
- `30000101` — умовна дата «не визначено»; показувати умову з `eds[].comment`.
- `pridat` — дата прийняття, а не набрання чинності редакцією.
- `is_archive` — `0|1`, не `isArchive`.
- Портал пише `charset=widows-1251`.
- Вік щойно записаного файлу може бути від'ємним (частки мс) — строк кешу `<= 0` означає «перевіряти завжди».
- `npm test` — це `node --test` (без шляху: `node --test test/` не працює на всіх версіях).
- Windows: PowerShell блокує `npx.ps1` — у інструкціях писати `npx.cmd`; ChatGPT вимагає віддалений HTTPS (тунель + секретний шлях); навички Codex — у `~/.agents/skills`.
- Push тегів може бути заборонено середовищем — реліз створює власник через «Publish release», workflow спрацьовує на `release: published`.
- Не пиши в CHANGELOG технічним жаргоном: читачі — юристи.
